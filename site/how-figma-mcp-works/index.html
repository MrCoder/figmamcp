How Figma MCP works, from your request to your file

Your agent, Claude Code or Codex, calls tools on a small MCP server on your Mac. The server passes each call to a plugin in the Figma desktop app. The plugin reads or edits the file you have open and sends the result back.

The three parts

The parts of FigmaMCP
Part Where it runs What it does
Your agentClaude Code or CodexReads your request and decides which tool to call.
The MCP serverOn your MacOffers the tools to the agent and passes each call on.
The pluginInside the Figma desktop appReads and edits the file you have open, then returns the result.

The server talks to the plugin, and the plugin acts in the file through Figma’s Plugin API. There is no Figma access token to create or paste.

One request, step by step

  1. You ask

    For example: “Rename every layer called Frame 12 to match its heading.”

  2. The agent reads first

    It calls page_info and node_info to find the layers and their exact names.

  3. The agent writes

    It calls a write tool and passes each current name back. A wrong name is refused.

  4. The plugin checks and acts

    The plugin checks scope and names. If they pass, it makes the change in your file.

  5. The agent checks

    It can read the layers again, or export a picture with node_export_visual.

How to use it

  1. Install

    Download the Mac app and follow its checklist. See Figma MCP setup.

  2. Open a file

    Use the Figma desktop app.

  3. Ask

    Ask Claude Code or Codex. Name the page or frame, and say what must stay the same.

  4. Review

    Look at the result. Use Figma version history to go back.

Why it reads before it writes

The file is a live document. You or a teammate may rename or move a layer between two calls. So the agent reads the current names first, and each write passes them back. If a name no longer matches, the plugin refuses the edit, and the agent reads again. This is how a wrong target gets caught before it changes anything.

For the parts behind this, including the local relay, the error codes and the bugs we fixed while building it, see how FigmaMCP is built.

What keeps it in bounds

  • Edits go only to the open file where the plugin’s AI can edit this file switch is on. With it off, the agent can only read.
  • Each edit names its target, and the name must match.
  • Bulk edits are checked first. If one item is invalid, nothing changes.
  • A wrong edit that follows the rules still goes through, so review.

Your agent sends what it reads to its own model provider, under that provider’s terms. FigmaMCP sends no design content to us. For background, see what is a Figma MCP server and edit Figma with AI.

What you should know first

  • macOS only for now.
  • It needs the Figma desktop app. It does not run in the browser.
  • FigmaMCP is not on Figma Community. The Mac app installs the plugin for you.
  • If you do not allow Accessibility, open the plugin once in each file (Plugins, Development, FigmaMCP) and leave it open while your agent edits.
  • Features that belong to Figma itself, such as Dev Mode, are not included.

Questions

How does Figma MCP work in one sentence?
Your agent calls tools on a local MCP server, and a plugin inside the Figma desktop app reads or edits your open file and returns the result.
What does FigmaMCP actually do?
It reads your file and can create and change layers, components, styles and variables. It does not generate code and it does not import HTML.
Do I need to learn commands to use it?
No. You ask your agent in plain words, and the agent picks the tools.
Does it work outside a Mac, or in the browser?
No. FigmaMCP supports macOS only for now, and it needs the Figma desktop app.
