Talk to Figma MCP alternative

With Talk to Figma MCP, you start a WebSocket server and join a channel before your agent can send a command. With FigmaMCP you do neither in the usual case: the free Mac app installs the plugin and connects Claude Code and Codex to the file open in Figma desktop. The two projects are related through figma-edit-mcp. FigmaMCP runs on macOS only.

Facts about Talk to Figma MCP on this page are from the cursor-talk-to-figma-mcp README by sonnylazuardi, checked 2026-11-19. They paraphrase the README and may change.

What Talk to Figma MCP asks of you

Talk to Figma MCP lets an agent read and modify Figma designs. Its README lists these setup steps: install Bun, run its setup script (which also installs the MCP server into your active Cursor project), start the WebSocket server, install the Figma plugin from Figma Community or link the local manifest, then run the plugin and join a channel with the join_channel tool. Both the WebSocket server and the plugin must stay running, and the plugin must be joined to a channel before commands work.

The README names Cursor and Claude Code as clients; the repository description also mentions Codex. It has a separate Windows guide that runs through WSL and needs a hostname change in a source file. It also says image export is only partly supported and currently returns base64 text, that commands can throw exceptions, and that large designs need chunking. The README does not mention a token requirement. If a relay to start and a channel to join feel like too many moving parts, an alternative may help.

What FigmaMCP does differently

FigmaMCP is a free Mac app. It installs the Figma plugin for you and connects Claude Code and Codex, so there is no relay to start and no channel code to type in the usual case. If several files have the plugin open, your agent chooses one with channel_join. FigmaMCP has no call quota of its own and needs no API token.

FigmaMCP also checks every write. Edits only happen where the plugin’s “AI can edit this file” switch is on. Each edit names its target layer, and the name must match. FigmaMCP validates a batch before it runs, and failures return structured errors such as NAME_MISMATCH or READ_ONLY_MODE.

How the two projects are related

FigmaMCP is a fork of figma-edit-mcp by Neo Product LLC. Notices in that project credit sonnylazuardi, so FigmaMCP descends from the Talk to Figma line of work via figma-edit-mcp. It is a separate project with its own setup and guardrails.

When Talk to Figma MCP is still the better pick

Talk to Figma MCP is the better pick if you use Cursor, or if you are not on a Mac. You can also read and change its code, and its tool list covers many areas: annotations, prototyping connections, components and styles, auto layout, text editing and export. If you want the plugin from Figma Community, its README points to that page. FigmaMCP is not on Figma Community.

When FigmaMCP fits

FigmaMCP fits if you use Claude Code or Codex on a Mac and want setup done for you. It suits people who want the edit switch and the layer-name check on every write. FigmaMCP needs the Figma desktop app and does not include Figma features such as Dev Mode. See setup and Codex setup.

Questions

Is there an alternative to Talk to Figma MCP without a WebSocket server?
FigmaMCP runs a local server for you inside a Mac app, so you do not start a relay or type a channel code in the usual case. It runs on macOS only and supports Claude Code and Codex.
Does Talk to Figma MCP work with Claude?
Its README names Claude Code next to Cursor. Source: the cursor-talk-to-figma-mcp README, checked 2026-11-19.
Is FigmaMCP the same project as Talk to Figma MCP?
No. FigmaMCP is a fork of figma-edit-mcp by Neo Product LLC, whose notices credit sonnylazuardi. It descends from the Talk to Figma line of work via figma-edit-mcp, and it is a separate project.
Is FigmaMCP affiliated with Figma?
No. FigmaMCP is independent and is not endorsed by Figma, Inc.
