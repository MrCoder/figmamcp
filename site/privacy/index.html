Privacy

FigmaMCP counts how often the website and the FigmaMCP plugin are used. It uses Google Analytics and a tiny image that Cloudflare counts. The plugin sends its version, a random install ID and counts of tool calls. From version 0.1.24, the FigmaMCP relay on your Mac and the Mac app also send a few usage events to Mixpanel through our own server, without your IP address. We send no file name, file key or design content, and we use no advertising features. An email address is stored only if you choose to join the email list.

What we count

  • Website: page views, clicks on links that leave the site, clicks on the Mac download button, and rough location (country) and device type, with Google Analytics 4.
  • Plugin: one event each time the FigmaMCP panel opens, with the plugin version and Google’s country from the request. The first time the plugin runs, it makes up a random install ID (16 hex digits) and keeps it in Figma’s plugin storage on your computer. Each load sends that ID, so we can count how many installs there are. The ID is random: it contains nothing about you, your Figma account or your files. To reset it, remove and re-add the plugin in Figma.
  • Both the site and the plugin also request /p.gif, a 1x1 transparent image, which we count by version, country and install ID. On the homepage only, a site visit also sends which locale homepage it was (for example zh or ja), from a fixed list, so we can see which locale homepage is visited; it is not a path or a query string, and it carries no install ID. Since 26 November 2026, the image request for a page view of this website also records the page path (without any query string, cut at 100 characters), the domain of the site that sent you here (for example www.google.com, never the full address; empty if you came from this site or from no site), and the campaign tag from a utm_source link, if the link has one. We use these to see which sites and links bring visitors. They go into the same count, with no cookie, no install ID and no IP address, and they are not sent to Mixpanel.
  • Tool-call counts: the plugin counts the AI tool calls it runs and sends the totals in batches to /u.gif: the first call of a plugin session at once, then 15 seconds after the first unsent call and at most once a minute while calls continue, or at once every 20 calls. Totals not yet sent stay in the plugin’s own Figma storage on your computer and are sent the next time the plugin opens. A plugin that is open checks every minute for totals left by a plugin that closed at least 5 minutes ago and sends them. Each batch has the plugin version, the install ID, how many calls worked and how many failed, and how many times each tool was used, by tool name (for example node_info:3). For failed calls it also has the tool name and the error code the plugin returned (for example node_delete:NAME_MISMATCH:1). It never contains file content, layer names, node IDs, text or file names.
  • Page speed: Cloudflare Web Analytics, which Cloudflare adds to each page, loads a small script from static.cloudflareinsights.com. It reports the page path, page load timing and Core Web Vitals, and the browser and operating system type, to Cloudflare. It sets no cookies and stores nothing in your browser. It runs even when your browser sends Do Not Track or Global Privacy Control.
  • Mac app: each time the FigmaMCP app starts, it also sends one launch count to /p.gif with its version and a random app ID (16 hex digits, made once and kept on your Mac), and no file contents. Every 24 hours the app also asks GitHub whether a newer version exists; that request carries no ID.
  • Client-connected count: once per plugin session, when an AI assistant actually connects (even if it never calls a tool), the plugin requests /c.gif with the plugin version, country and install ID — nothing else.
  • Download count: each request to /download adds one count with the country, a bot or human flag (guessed from the browser name, which is not stored) and the host of the site that linked to it, for example news.ycombinator.com. No IP address and no full referring address.

Usage events (Mixpanel)

From version 0.1.24, FigmaMCP also sends usage events to Mixpanel, so we can see which tools work and where people get stuck. The events come from the FigmaMCP relay, the small local program on your Mac that passes messages between your AI assistant and the plugin, and from the Mac app. They go first to figmamcp.dev/mp/track, our Cloudflare Worker. It accepts only the events and fields listed below and refuses everything else. It adds your country (from Cloudflare) and sends the events to Mixpanel with IP collection turned off, so Mixpanel never gets your IP address.

  • plugin_opened: the plugin panel connected to the relay, with the plugin version.
  • ai_connected: the first AI assistant connected in this plugin session, with the assistant’s name from a fixed list (claude-code, codex, cursor, claude or other). The session title or folder name the panel shows is never sent.
  • tool_called: one event per tool call, with the tool name (for example node_info), whether it worked, the error code if it failed (for example READ_ONLY_MODE, never the error message) and how long it took in milliseconds.
  • app_launched: the Mac app started, with the app version. This event uses the app’s random app ID instead of the plugin’s install ID.
  • Every event also has: product (always figmamcp), the relay version, the plugin version, the operating system and its major version (for example macOS 26), the random install ID (or app ID), the time, a random event ID used to remove duplicates, the country code from Cloudflare, and a flag that marks our own test installs.
  • Copies of the counts above: from 22 November 2026, each /p.gif, /c.gif, /u.gif and /download count is also sent to Mixpanel as one event (px_plugin_loaded, px_app_launched, px_connected, px_usage, site_visited or download), with the same fields the count already has and without your IP address. A site visit has only the country and the homepage locale code; a download has only the country, the bot or human flag and the referring host. Each site visit and download gets a new random ID, so they cannot be linked to each other or to an install.
  • Never sent: file names, file keys, layer or node names, node IDs, text, design content, prompts, folder paths, user names, email addresses or IP addresses.
  • If your Mac is offline, the relay keeps up to 1,000 unsent events (at most 1 MB) in ~/.figmamcp/telemetry-queue.jsonl and sends them when it can. Events older than five days are deleted without being sent.

Turning usage events off

  • Add "telemetry": false to ~/.figmamcp/config.json, for example {"port": 3155, "telemetry": false}. The relay and the Mac app then send no Mixpanel events, and the relay deletes its queue file the next time it would send.
  • Or set the environment variable FIGMAMCP_TELEMETRY=0 for your AI assistant. The FigmaMCP server it starts tells the relay, and the relay sends no ai_connected or tool_called events for that assistant. The relay itself starts at login, so the config key is the switch that covers everything.
  • These switches turn off the relay and Mac app events only. The /p.gif, /c.gif and /u.gif counts above, which the plugin sends from inside Figma, still run, and their copies still reach Mixpanel.

Cookies and choices

  • On the website, Google Analytics sets cookies, except for visitors in the EEA, the UK and Switzerland. For them it sets no analytics cookie and gets cookieless pings only.
  • If your browser sends Do Not Track or Global Privacy Control, the site does not load Google Analytics at all.
  • The plugin sets no cookies. It stores two things in Figma’s plugin storage on your computer: a random install ID (16 hex digits) and a flag that records you have seen the first-use example prompt.
  • We turn off Google Signals and ad personalisation. Nothing here is used for advertising.

What we do not collect

  • No account or device identifier. No email address, unless you choose to give one (see below).
  • No file name, file key, layer names or design content.
  • FigmaMCP does not store IP addresses. Google Analytics 4 does not log or store IP addresses either. Mixpanel does not get them: our server sends usage events with IP collection turned off.

Email list (optional)

  • If you type your email into a signup form on this site, we store that address, which form you used (for example the download or footer form) and the date and time. Nothing else.
  • Signing up is optional. Downloads and every page work without it.
  • We use the address only to send FigmaMCP setup tips and news about new tools. We do not sell or share it, and we do not use it for advertising.
  • The list is stored in Cloudflare Workers KV. To stop abuse, the form counts attempts per visitor for one hour using a one-way hash of the IP address; the IP address itself is not stored.
  • Every email has an unsubscribe link. To have your address deleted at any time, use that link or reply to any email.

Google

Google processes the Analytics data under its own privacy policy.

Mixpanel

Mixpanel, Inc. stores the usage events in its United States data center and processes them for us under its own privacy policy. Our server sends the events with IP collection turned off; the country comes from Cloudflare.

Cloudflare

This site is served through Cloudflare. Cloudflare processes every request, including the image request, and handles IP addresses under its own privacy policy. FigmaMCP does not store them. For Cloudflare Web Analytics, Cloudflare says it drops the IP address at the data center that receives the report.

Your agent

FigmaMCP sends no design content to us. Your AI agent does read what FigmaMCP returns from your file and passes it to its own model provider, under that provider’s terms. Choose your agent with that in mind.
