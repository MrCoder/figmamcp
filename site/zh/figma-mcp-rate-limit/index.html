Figma MCP 速率限制（按方案）

语言： English · 简体中文 · 日本語

Figma 官方的 MCP 服务器会限制一个账号能发起多少次调用。限额针对的是从 Figma 读取数据的工具；有些工具不计入，其中包括写入 Figma 文件的工具。本页按方案列出 Figma 公布的限额（2026-11-22 核实），并说明这对 Agent 处理设计意味着什么。

实际意味着什么

  • Agent 的工作中，碰到限额的是“看”的部分。一个任务如果先读页面，再读其中的框架，再读文字和样式，在改动任何东西之前就已经用掉了读取调用。
  • 以写入为主的任务用不了多少额度；以读取为主的任务很快就会用完。
  • 如果达到限额，可以让 Agent 减少读取、缩小范围：指定一个框架，而不是整个文件。其他办法见 Figma MCP limit reached（英文）页面。

FigmaMCP 有什么不同

FigmaMCP 是一个 Mac App，包含一个本地服务器和 Figma 桌面版里的一个插件。你的 Agent 和本地服务器通信，插件在你的 Mac 上通过 Figma 的 Plugin API 读取和编辑打开的文件。它不调用 Figma 的 MCP 服务器，所以 Figma 的 MCP 速率限制与它的工作方式无关，FigmaMCP 自己也没有调用次数配额。

这并不意味着 Figma 的所有规则都不适用。你的账号能否在文件里运行开发版插件，由 Figma 决定，我们也没有测试过每一种方案。在据此做计划之前，先在一个文件上试一试。另见 Official Figma MCP vs FigmaMCP（英文）和价格。

使用前须知

  • 目前仅支持 macOS。
  • 需要 Figma 桌面版，不能在浏览器中运行。
  • FigmaMCP 不在 Figma Community 上，由 Mac App 替你安装插件。
  • 如果不授予辅助功能权限，请在每个文件中打开一次插件（Plugins、Development、FigmaMCP），并在 Agent 编辑期间保持打开。
  • Figma 自身的功能（例如 Dev Mode）不包含在内。

常见问题

Figma MCP 的速率限制是多少？
取决于席位和方案。截至 2026-11-22，Figma 公布的限额是：View 或 Collab 席位在任何方案下每月最多 20 次；Full 或 Dev 席位在 Professional 方案下每天最多 200 次、每分钟 10 次，在 Organization 方案下每天 200 次、每分钟 15 次，在 Enterprise 方案下每天 600 次、每分钟 20 次。
Figma MCP 的写入调用计入限额吗？
不计入。Figma 表示，限额适用于从 Figma 读取数据的工具，有些工具不计入，其中包括写入 Figma 文件的工具。来源：Figma 的 rate limits and access 页面，2026-11-22 核实。
哪些调用会碰到限额？
读取工具，例如 get_design_context、get_metadata 和 get_screenshot。Agent 在编辑之前查看设计，首先用到的就是这些。
FigmaMCP 有调用次数限制吗？
FigmaMCP 没有自己的调用次数配额，也不调用 Figma 的 MCP 服务器。它通过 Figma 桌面版里的插件工作，所以你需要已有的文件访问权限，编辑则需要编辑权限。
