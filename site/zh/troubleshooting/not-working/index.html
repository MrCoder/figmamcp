Figma MCP 无法使用：按症状排查

语言： English · 简体中文 · 日本語

FigmaMCP 的问题大多出在三处：Agent 在安装前就已启动，插件没有打开，或者文件被设成了只读。本页只讲 FigmaMCP。Figma 官方服务器的问题请看 Figma 的文档。

症状、原因和解决办法
你看到的情况原因解决办法
下载很慢，或 curl 返回 403/download 跳转到的 GitHub 链接大约一小时后失效在浏览器里下载，或运行 curl -L -O https://github.com/MrCoder/figmamcp-releases/releases/latest/download/FigmaMCP.dmg。然后校验 SHA-256。
Agent 没有 Figma 工具它在安装前就已经在运行重启 Claude Code 或 Codex。
Plugins 菜单里没有 FigmaMCP插件没有安装打开 FigmaMCP App，点击 Add to Figma。
PLUGIN_PEER_UNAVAILABLE，或没有已连接的插件这个文件里没有打开插件在桌面版中打开文件，然后选择 Plugins › Development › FigmaMCP。想让 App 替你做这一步，就允许辅助功能权限。

工具没有加载

AI App 里看不到 FigmaMCP 的工具，或者它说自己没有 Figma 工具。按下面的顺序逐项检查，工具出现就可以停下。

  1. 退出并重新打开 Claude Code 或 Codex。 正在运行的 App 只在启动时读取 MCP 设置。安装时已经开着的 App，要退出再打开，才能看到 FigmaMCP。
  2. 在 Figma 文件里打开插件。 在 Figma 桌面版中选择 Plugins › Development › FigmaMCP。如果面板显示 “No AI app has FigmaMCP loaded yet”，说明第 1 步的重启还没生效。如果显示 “FigmaMCP isn’t running”，请打开 FigmaMCP App，插件会自己重新连接。
  3. 确认插件已经安装。 如果 Plugins 菜单里没有 FigmaMCP，见 plugin not showing（英文）。
  4. 确认你说的是哪个 Figma 工具。 Claude 内置的 Figma 连接器是另一个服务器，见下面的连接器部分。

如果工具已经列出来了，但调用返回 CHANNEL_NOT_BOUND，说明插件在多个文件里开着。把目标文件的 Figma 链接发给 Agent。

很慢或卡住

调用一直没有返回，插件显示 Connecting…，或者什么都没发生。

很慢或卡住：你看到的情况、原因和解决办法
你看到的情况原因解决办法
插件显示 “Connecting…” 或 “Can’t connect”插件在 3155 到 3158 端口上寻找本地服务，每 3 秒重试一次打开 FigmaMCP App，等几秒。面板会自己变成 Connected。
“The plugin did not respond. Trying again.”发出连接请求后 5 秒内，插件没有响应等下一次重试。如果一直重复，关闭插件再重新打开。
Agent 一直在等，Figma 里没有任何变化这个文件里没有打开插件，或者插件在多个文件里开着，或者文件是在浏览器版 Figma 里打开的在 Figma 桌面版中打开文件，并在那里打开插件。开了多个文件时，把目标文件的链接发给 Agent。
Agent 启动后的第一次调用返回 CONNECTION_NOT_READY本地连接还没建立打开 FigmaMCP App 和插件，然后重试。
读取大文件超时（PAGE_LOAD_TIMEOUT）某个页面没有及时加载完重试一次。如果还是超时，让 Agent 一次只读一个页面或一个图层。

条件不变，重试的结果也不会变，所以先解决原因。编辑失败时，重复之前先确认它有没有生效。

Claude 的 Figma 连接器无法使用

Claude 内置的 Figma 连接器就是 Figma 官方的远程服务器。它运行在 Figma 的托管服务上，不在你的 Mac 上。FigmaMCP 是另一个工具：一个免费的本地插件服务器，处理的是 Figma 桌面版里打开的文件。两者不共用连接，所以上面的表格解释不了连接器的问题。

  • 方案或席位限额：官方服务器按方案限制调用次数。View 或 Collab 席位每月 20 次，Pro 方案的 Full 或 Dev 席位每天 200 次。2026 年 11 月 25 日核实。见 Figma MCP 速率限制。
  • 编辑需要 Full 席位：远程服务器的写入画布功能还在测试阶段，在草稿以外的文件里需要 Full 席位。可能出现读取正常、编辑失败的情况。
  • 想用的不是这个服务器：如果要让 Agent 使用 FigmaMCP，需要先在 Mac 上安装好，并重启 Agent。按安装指南操作。

官方服务器自身的错误，请看 Figma 的文档。两者有什么区别，见 Official Figma MCP vs FigmaMCP（英文）。

还是解决不了？

到发布页提交 issue。写明你让 Agent 做了什么、确切的错误信息和 macOS 版本。不要附上私密的设计内容。另见安装指南。

常见问题

为什么 AI App 里看不到 FigmaMCP 的工具？
正在运行的 Claude Code 或 Codex 只在启动时读取 MCP 设置。退出后重新打开，并让插件在 Figma 文件里保持打开。
为什么插件一直显示 Connecting…？
插件在 3155 到 3158 端口上寻找本地服务，每 3 秒重试一次。打开 FigmaMCP App，它就会自己连上。
出了问题需要重装吗？
通常不需要。确认 Agent 已经重启、插件已经打开、开关已经打开。
为什么重试还是同样的错误？
这些错误来自固定的规则。先改变条件，例如打开插件，或者重新读取图层名。
本页适用于 Figma 官方的 MCP 服务器吗？
不适用。本页只讲 FigmaMCP。
