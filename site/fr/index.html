FigmaMCP est un outil gratuit et local qui permet à Claude Code ou Codex de lire et modifier un fichier ouvert dans l'application de bureau Figma. Il fonctionne sur votre Mac via l'API Plugin de Figma, donc il n'y a aucun quota d'appels à surveiller.

Voir FigmaMCP à l’œuvre

Ce qu'il fait

Dites à votre agent ce que vous voulez, en langage courant. Il lit la structure de votre fichier ouvert, puis effectue les modifications dans ce même fichier, où vous pouvez les voir se produire.

Lire

Pages, cadres, calques, texte, composants, variables et styles du fichier que vous avez sous les yeux.

Modifier

Créez et modifiez des cadres, du texte, des formes, des composants et instances, l'auto layout, les remplissages, contours et effets.

Appliquer à grande échelle

Renommez, restylez ou réécrivez de nombreux calques en une seule demande, par exemple chaque calque de texte mentionnant un ancien nom de produit.

Rester dans des limites sûres

Chaque modification doit nommer précisément sa cible, une modification groupée avec un seul élément invalide ne change rien, et un interrupteur du plugin peut rendre le fichier en lecture seule.

Comment ça marche

  1. Téléchargez et ouvrez l'application

    Téléchargez FigmaMCP pour Mac et ouvrez-le. Il réside dans votre barre de menus.

  2. Cliquez sur Add to Figma

    Figma redémarre une seule fois, et seulement s'il était en cours d'exécution et que le plugin manquait. Vous pouvez aussi autoriser l'accès Accessibilité pour que FigmaMCP puisse ouvrir le plugin à la place de votre IA.

  3. Demandez à votre agent

    Demandez à Claude Code ou Codex de modifier votre fichier ouvert. Rien à importer, aucun code à coller, aucun port à choisir.

À savoir avant de commencer

  • Pour l'instant, macOS uniquement.
  • Nécessite l'application de bureau Figma. Ne fonctionne pas dans le navigateur.
  • FigmaMCP n'est pas sur Figma Community. L'application Mac installe le plugin pour vous.
  • Si vous n'autorisez pas l'accès Accessibilité, ouvrez le plugin une fois dans chaque fichier (Plugins, Development, FigmaMCP) et laissez-le ouvert pendant que votre agent modifie.
  • Les fonctionnalités propres à Figma, comme le Dev Mode, ne sont pas incluses.

Questions

FigmaMCP est-il vraiment gratuit ?
Oui. Il est gratuit et n'a pas de palier payant. Il n'appelle pas le serveur MCP hébergé par Figma, donc les limites d'appels par siège de Figma ne s'appliquent pas. Votre propre forfait Figma et les conditions de Figma s'appliquent toujours au fichier que vous ouvrez.
En quoi est-il différent du serveur MCP officiel de Figma ?
Le serveur officiel de Figma est de première partie et fonctionne avec de nombreux clients MCP. Sur les forfaits plus modestes, ses appels de lecture sont plafonnés, et ses écritures sur le canevas sont en bêta et exigent un siège Full en dehors des brouillons. FigmaMCP s'exécute sur votre Mac via un plugin dans le fichier que vous avez ouvert, sans jeton API et sans quota d'appels. Il fonctionne avec Claude Code et Codex, sur macOS uniquement. Voir la comparaison complète.
Si deux personnes ont le même fichier ouvert, dans quel Figma l'agent édite-t-il ?
Dans l'application de bureau Figma du Mac où l'agent s'exécute. L'agent parle au plugin de cette application ; il édite donc au nom de cette personne, qui doit avoir un accès en édition au fichier. Tous les autres voient les modifications en direct, comme n'importe quelle autre modification. Si deux personnes modifient le même calque au même instant, c'est la synchronisation multijoueur propre à Figma qui tranche : les modifications de propriétés différentes sont toutes conservées, et pour une même propriété, la dernière modification l'emporte. FigmaMCP n'ajoute aucune étape de fusion de son côté.
Fonctionne-t-il sur Windows ou Linux ?
Pas encore. FigmaMCP ne prend en charge que macOS pour l'instant.
Ai-je besoin d'un jeton API Figma ?
Non. FigmaMCP communique avec l'application de bureau Figma sur votre Mac via l'API Plugin, il n'y a donc aucun jeton d'accès à créer ou à coller.
Pourquoi le plugin n'est-il pas sur Figma Community ?
FigmaMCP est distribué hors de Figma Community. Vous ne l'installez pas à la main : l'application Mac l'enregistre dans Figma pour vous, et il apparaît ensuite sous Plugins, Development.
Avec quels agents fonctionne-t-il ?
Claude Code et Codex sont les cibles testées, et l'application Mac les connecte pour vous.
L'agent peut-il abîmer mon fichier ?
Les modifications ne s'appliquent qu'au fichier où le plugin est ouvert et où l'interrupteur AI can edit this file est activé ; désactivez-le et l'IA ne pourra que lire. Chaque modification doit nommer précisément son calque cible. Les modifications groupées sont vérifiées avant tout changement. Cela reste un outil d'édition : vérifiez le résultat comme vous le feriez pour le travail d'un collègue, et utilisez l'historique des versions de Figma.
Envoie-t-il des requêtes aux serveurs de Figma ?
Non. FigmaMCP n'appelle ni les serveurs de Figma ni son API REST. Votre agent parle à un serveur MCP local, qui parle au plugin dans l'application de bureau Figma via localhost, et le plugin lit et modifie le fichier via l'API Plugin à l'intérieur de l'application. Vos modifications atteignent ensuite le cloud de Figma de la même façon que vos propres modifications, via la synchronisation normale de l'application. Les seules requêtes envoyées par le plugin lui-même ne contiennent jamais le contenu du fichier : un comptage de démarrage par lancement du plugin, avec la version du plugin et un identifiant d'installation aléatoire, vers figmamcp.dev et Google Analytics, ainsi que des comptages groupés d'appels d'outils par nom d'outil, sans contenu, vers figmamcp.dev.
Mon design quitte-t-il ma machine ?
FigmaMCP lui-même n'envoie aucun contenu de fichier où que ce soit. Votre agent, cependant, lit ce que FigmaMCP renvoie et l'envoie à son propre fournisseur de modèle, selon les conditions de ce dernier. Voir la page de confidentialité.
Est-ce fait par Figma ?
Non. Aucune affiliation ni approbation de Figma, Inc. FigmaMCP est un fork de figma-edit-mcp par Neo Product LLC.
