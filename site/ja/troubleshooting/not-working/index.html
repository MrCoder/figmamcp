Figma MCPが動かないとき：症状から探す

言語： English · 简体中文 · 日本語

FigmaMCPの問題の多くは、セットアップ前からエージェントが起動していた、プラグインが開いていない、ファイルが読み取り専用になっている、のいずれかが原因です。このページはFigmaMCPについてのものです。Figma自身のサーバーについてはFigmaのドキュメントをご覧ください。

症状、原因、対処法
起きていること原因対処法
ダウンロードが遅い、または curl で403になる/download のリダイレクト先のGitHubリンクが約1時間で期限切れになるブラウザでダウンロードするか、curl -L -O https://github.com/MrCoder/figmamcp-releases/releases/latest/download/FigmaMCP.dmg を実行します。そのあとSHA-256を確認します。
エージェントにFigmaのツールがないセットアップ前から起動していたClaude CodeまたはCodexを再起動します。
PluginsメニューにFigmaMCPがないプラグインがインストールされていないFigmaMCPアプリを開き、Add to Figmaをクリックします。
PLUGIN_PEER_UNAVAILABLE、またはプラグインが接続されていないこのファイルでプラグインが開いていないデスクトップアプリでファイルを開き、Plugins › Development › FigmaMCPを選びます。アプリに任せたい場合は、アクセシビリティを許可してください。
CHANNEL_NOT_BOUND、またはエージェントがどのファイルか尋ねてくる複数のファイルでプラグインが開いている対象ファイルのFigmaリンクをエージェントに渡すか、ほかのファイルのプラグインを閉じます。

ツールが読み込まれない

AIアプリにFigmaMCPのツールが表示されない、またはFigmaのツールがないと言われる場合です。上から順に確認し、ツールが表示されたらそこで終わりです。

  1. Claude CodeまたはCodexを終了して開き直します。 起動中のアプリは、起動時にしかMCPの設定を読み込みません。セットアップ中に開いていたアプリは、終了して開き直すまでFigmaMCPを認識しません。
  2. Figmaファイルでプラグインを開きます。 FigmaデスクトップアプリでPlugins › Development › FigmaMCPを選びます。パネルに「No AI app has FigmaMCP loaded yet」と表示される場合は、手順1の再起動がまだ反映されていません。「FigmaMCP isn’t running」と表示される場合は、FigmaMCPアプリを開いてください。プラグインは自動で再接続します。
  3. プラグインがインストールされているか確認します。 PluginsメニューにFigmaMCPがない場合は、plugin not showing（英語）をご覧ください。
  4. どのFigmaツールのことかを確認します。 Claudeに組み込まれたFigmaコネクタは別のサーバーです。下のコネクタの項目をご覧ください。

ツールは表示されるのに、呼び出すと CHANNEL_NOT_BOUND が返る場合は、複数のファイルでプラグインが開いています。対象ファイルのFigmaリンクをエージェントに渡してください。

遅い・止まる

呼び出しが返ってこない、プラグインがConnecting…のまま、または何も起きない場合です。

遅い・止まる：起きていること、原因、対処法
起きていること原因対処法
プラグインに「Connecting…」または「Can’t connect」と表示されるプラグインはポート3155〜3158でローカルサービスを探し、3秒ごとに再試行するFigmaMCPアプリを開いて数秒待ちます。パネルは自動でConnectedに変わります。
「The plugin did not respond. Trying again.」接続要求から5秒以内にプラグインが応答しなかった次の再試行を待ちます。何度も繰り返す場合は、プラグインを閉じて開き直します。
エージェントが待ったままで、Figmaに何も変化がないこのファイルでプラグインが開いていない、複数のファイルで開いている、またはブラウザ版Figmaでファイルを開いているFigmaデスクトップアプリでファイルを開き、そこでプラグインを開きます。複数のファイルを開いている場合は、対象ファイルのリンクをエージェントに渡します。
エージェント起動後の最初の呼び出しが CONNECTION_NOT_READY で失敗するローカル接続がまだ開いていなかったFigmaMCPアプリとプラグインを開いてから、もう一度試します。
大きなファイルの読み取りがタイムアウトする（PAGE_LOAD_TIMEOUT）ページの読み込みが時間内に終わらなかった一度だけ再試行します。またタイムアウトする場合は、1ページまたは1レイヤーずつ読むようエージェントに頼みます。

条件が変わらない限り、再試行しても結果は同じです。先に原因を解消してください。編集が失敗した場合は、繰り返す前に反映済みかどうかを確認します。

ClaudeのFigmaコネクタが動かない

Claudeに組み込まれたFigmaコネクタは、Figma公式のリモートサーバーです。Mac上ではなく、Figmaのホスト型サービスで動いています。FigmaMCPは別のツールで、Figmaデスクトップアプリで開いているファイルを対象に動く、無料のローカルプラグインサーバーです。両者は接続を共有しないため、上の表ではコネクタの問題は説明できません。

  • プランやシートの上限：公式サーバーには、プランごとの呼び出し上限があります。View または Collab シートは月20回、ProのFullまたはDevシートは1日200回です（2026年11月25日確認）。Figma MCP レート制限をご覧ください。
  • 編集にはFullシートが必要：リモートサーバーでのキャンバスへの書き込みはベータ版で、下書き以外ではFullシートが必要です。読み取りは動くのに、編集だけ失敗することがあります。
  • 想定しているサーバーが違う：エージェントにFigmaMCPを使わせたい場合は、Macにセットアップしてエージェントを再起動する必要があります。セットアップガイドに沿って進めてください。

公式サーバー自体のエラーについてはFigmaのドキュメントを、両者の違いについてはOfficial Figma MCP vs FigmaMCP（英語）をご覧ください。

それでも解決しない場合

リリースページでIssueを作成してください。何を頼んだか、正確なエラー、macOSのバージョンを書いてください。非公開のデザイン内容は含めないでください。セットアップガイドもあわせてご覧ください。

よくある質問

AIアプリにFigmaMCPのツールが表示されないのはなぜですか？
起動中のClaude CodeやCodexは、起動時にしかMCPの設定を読み込みません。終了して開き直し、Figmaファイルでプラグインを開いたままにしてください。
プラグインがConnecting…のままなのはなぜですか？
プラグインはポート3155〜3158でローカルサービスを探し、3秒ごとに再試行します。FigmaMCPアプリを開けば、自動で接続します。
何か失敗したら再インストールが必要ですか？
たいていは不要です。エージェントを再起動したか、プラグインが開いているか、スイッチがオンになっているかを確認してください。
再試行しても同じエラーになるのはなぜですか？
これらのエラーは決まったルールから出ています。先に条件を変えてください。たとえばプラグインを開く、レイヤー名を読み直す、といった対応です。
このページはFigma公式のMCPサーバーにも当てはまりますか？
いいえ。FigmaMCPだけを対象にしています。
