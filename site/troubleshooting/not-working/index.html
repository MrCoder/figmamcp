Figma MCP not working: find your symptom

Most FigmaMCP problems come from three things: the agent started before setup, the plugin is not open, or the file is set to read-only. This page covers FigmaMCP. For Figma’s own server, see Figma’s docs.

Tools not loading

Your AI app does not list FigmaMCP tools, or it says it has no Figma tools. Work down this list and stop when the tools appear.

  1. Quit and reopen Claude Code or Codex. A running app reads its MCP settings only when it starts. One that was open during setup does not see FigmaMCP until you quit it and open it again.
  2. Open the plugin in a Figma file. In the Figma desktop app, choose Plugins, Development, FigmaMCP. If the panel says “No AI app has FigmaMCP loaded yet”, the restart in step 1 has not taken effect. If it says “FigmaMCP isn’t running”, open the FigmaMCP app. The plugin reconnects by itself.
  3. Check that the plugin is installed. If FigmaMCP is not in the Plugins menu, see plugin not showing.
  4. Check which Figma tool you mean. Claude’s built-in Figma connector is a different server. See the connector section below.

If the tools are listed but a call returns CHANNEL_NOT_BOUND, the plugin is open in more than one file. Give your agent a Figma link to the file you mean.

Slow or stuck

A call hangs, the plugin shows Connecting…, or nothing happens.

Slow or stuck: what you see, cause and fix
What you seeCauseFix
The plugin shows “Connecting…” or “Can’t connect”The plugin looks for the local service on ports 3155 to 3158 and tries again every 3 secondsOpen the FigmaMCP app and wait a few seconds. The panel changes to Connected on its own.
“The plugin did not respond. Trying again.”The plugin did not answer within 5 seconds of the connect requestWait for the next try. If it keeps repeating, close the plugin and open it again.
The agent waits and nothing changes in FigmaThe plugin is not open in this file, or it is open in several files, or the file is in browser FigmaOpen the file in the Figma desktop app and open the plugin there. For several files, give your agent a link to the one you mean.
The first call after the agent starts fails with CONNECTION_NOT_READYThe local connection was not open yetOpen the FigmaMCP app and the plugin, then retry.
A read of a large file times out (PAGE_LOAD_TIMEOUT)A page did not finish loading in timeRetry once. If it times out again, ask your agent to read one page or one layer at a time.

A retry gives the same result until the condition changes, so fix the cause first. For a failed edit, check whether it applied before you repeat it.

Claude’s Figma connector not working

Claude’s built-in Figma connector is Figma’s official remote server. It runs on Figma’s hosted service, not on your Mac. FigmaMCP is a different tool: a free local plugin server that works on the file open in the Figma desktop app. The two do not share a connection, so the table above does not explain a connector problem.

  • Plan or seat limits: the official server has call limits by plan. A View or Collab seat gets 20 calls a month, and Pro Full or Dev gets 200 a day. Checked November 22, 2026. See Figma MCP rate limit by plan.
  • Edits need a Full seat: writing to the canvas is in beta on the remote server, and it needs a Full seat outside drafts. Read calls can work while edits fail.
  • Wrong server in mind: if your agent should use FigmaMCP, it must be set up on your Mac and the agent restarted. Follow the setup guide.

For the official server’s own errors, use Figma’s docs. For the differences between the two, read Official Figma MCP vs FigmaMCP.

Still stuck?

Open an issue on the releases page. Include what you asked, the exact error and your macOS version. Do not include private design content. See also the setup guide.

Questions

Why does my AI app not show FigmaMCP tools?
A running Claude Code or Codex reads its MCP settings only when it starts. Quit it, open it again, and keep the plugin open in your Figma file.
Why does the plugin stay on Connecting…?
The plugin looks for the local service on ports 3155 to 3158 and tries again every 3 seconds. Open the FigmaMCP app and it connects by itself.
Do I need to reinstall when something fails?
Usually not. Check that your agent was restarted, that the plugin is open, and that the switch is on.
Why does a retry give the same error?
These errors come from fixed rules. Change the condition first, for example open the plugin or refresh the layer name.
Does this page apply to Figma's official MCP server?
No. It covers FigmaMCP only.
