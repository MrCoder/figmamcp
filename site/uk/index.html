Ваш агент редагує файл Figma, який у вас уже відкритий.

Мова: English · 简体中文 · 繁體中文 · 日本語 · Polski · Français · Deutsch · 한국어 · Українська

FigmaMCP — безкоштовний локальний інструмент, який дозволяє Claude Code або Codex читати та редагувати відкритий файл у десктопному застосунку Figma. Він працює на вашому Mac через Plugin API Figma, тож стежити за лімітом викликів не потрібно.

Завантажити для Mac Version 0.1.25 macOS 14 або новіше · Intel та Apple Silicon · приблизно 155 МБ

Завантаження почалося. Відкрийте FigmaMCP.dmg і перетягніть застосунок у Applications. Інструкція з встановлення.

Як це виглядає

Що він уміє

Скажіть агенту звичайною мовою, що вам потрібно. Він прочитає структуру відкритого файлу, а потім внесе зміни прямо в ньому — ви побачите, як вони відбуваються.

Читання

Сторінки, фрейми, шари, текст, компоненти, змінні й стилі з файлу, який у вас відкритий.

Редагування

Створюйте та змінюйте фрейми, текст, форми, компоненти й інстанси, auto layout, заливки, контури та ефекти.

Застосування масово

Перейменовуйте, змінюйте стиль або переписуйте багато шарів одним запитом — наприклад, кожен текстовий шар зі старою назвою продукту.

У межах безпечного

Кожна зміна має точно вказувати ціль, масова зміна з одним недійсним елементом не змінює нічого, а один перемикач у плагіні може зробити файл лише для читання.

Як це працює

  1. Завантажте і відкрийте застосунок

    Завантажте FigmaMCP для Mac і відкрийте його. Він живе у вашій панелі меню.

  2. Натисніть Add to Figma

    Figma перезапуститься лише один раз, і тільки якщо вона вже була запущена, а плагіна ще не було. Можна також дозволити доступ до спеціальних можливостей (Accessibility), щоб FigmaMCP міг відкривати плагін за вашу AI.

  3. Попросіть агента

    Попросіть Claude Code або Codex змінити відкритий файл. Нічого імпортувати, жодного коду вставляти і жодного порту обирати не потрібно.

Що варто знати спочатку

  • Поки що лише для macOS.
  • Потрібен десктопний застосунок Figma. У браузері не працює.
  • FigmaMCP немає в Figma Community. Застосунок для Mac встановлює плагін за вас.
  • Якщо не дозволити доступ до спеціальних можливостей, відкрийте плагін один раз у кожному файлі (Plugins, Development, FigmaMCP) і залишайте його відкритим, доки агент редагує.
  • Функції, що належать самій Figma, як Dev Mode, не входять до складу.

Поширені запитання

Чи FigmaMCP справді безкоштовний?
Так. Він безкоштовний і не має платного рівня. Він не викликає MCP-сервер, хостинг якого забезпечує Figma, тож ліміти викликів на одне місце в Figma на нього не поширюються. До файлу, який ви відкриваєте, усе одно застосовуються ваш власний план Figma та умови Figma.
Чим він відрізняється від офіційного MCP-сервера Figma?
Офіційний сервер Figma створює сама Figma, і він працює з багатьма MCP-клієнтами. На менших планах його виклики читання обмежені, а запис на полотно перебуває в бета-версії й поза чернетками потребує місця Full. FigmaMCP працює на вашому Mac через плагін у відкритому файлі, без токена API і без квоти викликів. Він працює з Claude Code і Codex, лише на macOS. Дивіться повне порівняння.
Якщо двоє людей відкрили той самий файл, чию Figma редагує агент?
Десктопний застосунок Figma на тому Mac, де працює агент. Агент спілкується з плагіном у цьому застосунку, тож редагує від імені цієї людини, якій потрібен доступ до редагування файлу. Решта бачать зміни наживо, як будь-яке інше редагування. Якщо двоє змінюють той самий шар одночасно, це розв'язує власна багатокористувацька синхронізація Figma: зміни різних властивостей зберігаються обидві, а для тієї самої властивості перемагає остання зміна. FigmaMCP не додає власного кроку злиття.
Чи працює на Windows або Linux?
Ще ні. FigmaMCP поки що підтримує лише macOS.
Чи потрібен токен API Figma?
Ні. FigmaMCP спілкується з десктопним застосунком Figma на вашому Mac через Plugin API, тож токена доступу створювати чи вставляти не потрібно.
Чому плагіна немає в Figma Community?
FigmaMCP поширюється поза Figma Community. Встановлювати його вручну не потрібно: застосунок для Mac реєструє його в Figma за вас, і потім він з'являється в Plugins, Development.
З якими агентами він працює?
Claude Code і Codex — перевірені цілі, і застосунок для Mac підключає їх за вас.
Чи може агент зіпсувати мій файл?
Зміни потрапляють лише у файл, де плагін відкритий і перемикач AI can edit this file увімкнений; вимкнувши його, AI може лише читати. Кожна зміна має точно вказувати цільовий шар. Масові зміни перевіряються, перш ніж бути застосованими. Це все одно інструмент редагування: перевіряйте результат так само, як перевіряли б роботу колеги, і користуйтеся історією версій Figma.
Чи надсилає запити на сервери Figma?
Ні. FigmaMCP не викликає сервери Figma чи її REST API. Ваш агент спілкується з локальним MCP-сервером, який спілкується з плагіном у десктопному застосунку Figma через localhost, а плагін читає й редагує файл через Plugin API всередині застосунку. Потім ваші зміни потрапляють у хмару Figma так само, як і ваші власні зміни — через звичайну синхронізацію застосунку. Запити, які надсилає сам плагін, ніколи не містять вмісту файлу: один підрахунок запуску на старт плагіна з версією плагіна та випадковим ідентифікатором встановлення — на figmamcp.dev і Google Analytics, а також згруповані підрахунки викликів за назвою інструмента, без вмісту, на figmamcp.dev.
Чи залишає мій дизайн мій комп'ютер?
Сам FigmaMCP нікуди не надсилає вміст файлу. Проте ваш агент читає те, що повертає FigmaMCP, і надсилає це своєму постачальнику моделі згідно з його умовами. Див. сторінку конфіденційності.
Це зроблено компанією Figma?
Ні. Не пов'язаний із Figma, Inc. і не має її підтримки. FigmaMCP — це форк figma-edit-mcp від Neo Product LLC.
